# Research and development diary

This diary records the project's research decisions, evidence and open questions. It is intended as a starting point for the research report, not as a substitute for experimental records or a claim of clinical or real-world validity. Entries describe work completed and distinguish observations from assumptions. Dates indicate when an entry was recorded; the first entry reconstructs earlier work from the project records.

## 7 November 2026 — Initial prototype and research review

### Research objective and scope

The project aims to investigate whether an Android application can identify potentially harmful language in social-media conversations while processing text on the device. Cyberbullying and grooming motivate the longer-term research, but the initial implementation addresses **toxicity only**. A toxicity score is not equivalent to a cyberbullying label, and the current system cannot reliably detect or rule out grooming.

We selected Android and English for the first prototype, with Instagram direct messages as the initial target. Android was chosen as the more practical platform for investigating accessibility-based access to visible interface text; this is a feasibility hypothesis, not evidence that Instagram exposes the necessary information. Italian, TikTok and a separate experience for parents are deferred. The initial user is the person using the phone, and the application does not send alerts to others.

### Privacy and acquisition strategy

We chose on-device processing to reduce the need to transfer sensitive conversations. The prototype has no internet permission, does not deliberately save conversation text and presents generic notifications without message content. Monitoring requires an explicit disclosure and user consent, and can be paused or stopped. The application starts with monitoring off after process death. These are design properties, not a completed privacy or security assessment.

For the initial Instagram experiment, the accessibility service is limited to the Instagram package and attempts to analyze only visible, non-editable nodes with a small set of candidate message identifiers in a recognizable chat screen. It also checks the active window, screen state and sensitive input types. The bounded queue and temporary deduplication reduce repeated processing and are cleared on pause or stop. These restrictions aim to limit collection, at the cost of possibly missing messages. The identifiers and chat recognition have **not been verified on a physical device**; coverage may be zero. The prototype cannot reliably identify message direction, conversation history, sarcasm or escalation.

Manual text entry was added as a separate input path so that model inference can be investigated even if Instagram does not expose suitable accessibility nodes. The planned more advanced contextual stage is not yet implemented.

### Review of AWARE

We reviewed [AWARE's Android client](https://github.com/awareframework/aware-client) at commit `f77e873baaedfc649fd39ca8f3547f914c3e6b32`. This review concerns that repository, not a verified assessment of a separate AWARE-Light implementation. AWARE traverses accessibility trees and includes duplicate and password-related checks, but its screen-text component also buffers and stores content and belongs to a larger sensing framework with features outside this prototype's scope.

We retained the focused application rather than replacing it with AWARE: the narrower design better matches the initial local-processing objective. We independently implemented additional checks inspired by the review; no AWARE source code was copied. Neither approach guarantees that Instagram exposes complete or usable chat text. Further details are recorded in [research.md](research.md).

### Initial model and deployment

We selected [unitary/toxic-bert](https://huggingface.co/unitary/toxic-bert), an English toxicity classifier, as an available research baseline rather than claiming to have selected an optimal model. Its outputs cover toxic language and related categories; they do not establish intent, identify an offender or provide a validated grooming assessment. The model and tokenizer can also make errors involving jokes, context and identity-related language.

The checkpoint was exported to ONNX for local inference through ONNX Runtime. The exported revision is `4d6c22e74ba2fdd26bc4f7238f50766b045a0d94`, and the unquantized ONNX file is 438,234,020 bytes. The alert threshold is a fixed experimental value of 0.5; it has not been calibrated for the intended use. A smaller or contextual model, quantization and a comparison of candidate models are future experiments, not established improvements.

The first export comparison produced a large discrepancy. We found that the reference model was not consistently in evaluation mode after export; repeating the export with evaluation mode set produced a maximum absolute logit difference of **0.00000465** across four examples. The Kotlin tokenizer also matched the reference tokenizer on four generated examples. These checks establish limited implementation consistency, not predictive quality or full Unicode compatibility.

### Initial evaluation

We created small, separate synthetic calibration and test sets to check that the pipeline runs. With the fixed 0.5 threshold, the 10-item synthetic test produced 5 true positives, 4 true negatives, 1 false positive and 0 false negatives. No threshold tuning was performed on either set. This smoke test is too small and artificial to support performance claims; the underlying report is [synthetic-evaluation.json](synthetic-evaluation.json).

We then downloaded the [Dadvar YouTube dataset](https://research.utwente.nl/en/datasets/underlying-dataset-of-experts-and-machines-against-bullies-a-hybr/), whose Zenodo record specifies CC BY 4.0. Its 3,464 usable rows contain comment histories associated with authors, rather than individually labeled Instagram messages. We ran an exploratory comparison on a balanced sample of 100 authors per class, with random seed 42, using the first 128 tokens and the existing 0.5 toxicity threshold. The result was 70 true positives, 55 true negatives, 45 false positives and 30 false negatives; 130 histories were truncated. The model was not trained or calibrated on this dataset during this project.

This is a **cross-task diagnostic**, comparing a toxicity score on a text window with an author-history bullying label. The balanced sample does not reflect dataset prevalence; source, age, truncation and unknown overlap with the model's training data further limit interpretation. It is not an estimate of message-level performance, Instagram performance or grooming detection. The reproducible method and results are in [research.md](research.md) and [dadvar-exploratory.json](dadvar-exploratory.json).

For future dataset selection, we identified the PAN 2012 sexual predator identification corpus and Wisconsin Bullying Traces as relevant sources, subject to their respective access and use conditions. We also reviewed the Ejaz et al. cyberbullying dataset: its authors describe generated users and assembled interactions, so its conversations should be treated as semi-synthetic rather than natural dialogue. We have not used these three sources to train or evaluate the current model.

### Build and outstanding validation

The Android debug application was built successfully, and three tokenizer unit tests passed. The debug APK is approximately 498 MB. At the time of the build no Android phone was connected, so installation, device inference, latency, memory, battery impact, Instagram accessibility coverage and notification behavior remain untested. The planned checks are recorded in [device-test.md](device-test.md).

The next research priorities are to test the acquisition mechanism on a physical phone using test accounts, measure on-device performance, establish task-appropriate datasets and labels, and evaluate models on held-out material without conflating toxicity, cyberbullying and grooming. Any future metrics should document their sampling, label meaning, potential data overlap and limits of generalization.

### Follow-up — conversational and private-message datasets

We investigated whether conversational datasets exist beyond public posts. The answer is yes, although their provenance and access differ considerably. We downloaded the open PAN12 archive locally and inspected its structure and accompanying documentation without displaying or publishing conversations. It contains separate training and test corpora, author labels and test line references. Many positive examples are drawn from adult decoy interactions rather than real minors' private chats; the corpus is old and has source-specific biases. Zenodo reports open access but does not state a license in the metadata field inspected, and the archive warns that some personal information may remain. We did not train or evaluate a model on PAN12. The archive is excluded from version control.

We also identified PANC for early grooming research, the FBK Italian WhatsApp role-play corpus for future cyberbullying experiments, and the restricted SecondLook dataset for digital dating abuse. FBK consists of human-written WhatsApp group interactions under fictional, supervised scenarios; it should not be presented as naturally occurring victimization. SecondLook's description alone does not establish that its messages are authentic private conversations. PANC shares sources with PAN12 and is not an independent test dataset. Further sources, access status and citations are documented in [research.md](research.md).

We selected PAN12 as the strongest immediately available grooming research candidate, not as proof that the prototype detects grooming. Decisions about using specific corpora in training or reporting require checking their terms, annotation units, research safeguards and overlap before experiments.

### Follow-up — PAN12 contextual baseline and broader dataset search

We built and ran a first **offline research baseline** on the PAN12 training archive only. It takes at most the first ten messages of each segment and uses TF-IDF with class-weighted logistic regression. The fixed 0.5 decision threshold was not tuned. The goal is to establish an interpretable starting point for future comparison, not to add a grooming detector to the Android application.

PAN12 labels authors rather than individual grooming messages, so segment labels were derived from author presence and a positive prefix was required to contain a labeled author's turn. To reduce leakage, the split groups all authors appearing in a full segment and identical prefix texts into connected components. Grouping necessarily limits flexibility: one component contains 22,506 segments, and the selected development set covers 9,043 of 66,901 usable segments, not the intended approximate 20%. The model input remains the first ten messages; the complete segment is used only to prevent authors crossing splits. Near-duplicates, author-derived weak labels and source artifacts remain limitations.

The development comparison produced 159 true positives, 20 false negatives, 366 false positives and 8,498 true negatives (precision 0.303; recall 0.888; F1 0.452; average precision 0.736). These figures do not validate real-time detection, single-message labels, or generalization to Instagram. The official PAN12 test archive was not used; no trained model or conversation texts were exported. Details and reproducibility are in [research.md](research.md) and [pan12-context-development.json](pan12-context-development.json).

The broader search identified additional relevant resources rather than an absence of data: research datasets include annotated Instagram comments, THREAT for violent threats, CAD for abuse in Reddit discussion context, and SynBullying's translated role-play and generated conversations. They differ in platform, annotation unit, authenticity, access and task. Some require a separate access request; none should be represented as a comprehensive private-Instagram benchmark without further evidence. The candidates and sources are recorded in [research.md](research.md).

### Follow-up — compact models, context and quantization

We built a common PAN12 pilot to compare models on the same author-grouped partitions, using only the original training archive. A resource-bounded sample contains 360 training segments, 210 threshold/calibration segments and 209 development segments. The class proportions were deliberately changed by sampling. For the selected examples we also checked 10-message windows for near duplicates using word-trigram similarity; the audit is incomplete. The official test archive was not used. The author-derived positive labels and the requirement that a labeled author appears in the first five messages do not demonstrate that grooming was already visible at that point.

The comparison includes a TF-IDF baseline, a frozen MobileBERT encoder with a fitted logistic head, and an end-to-end MobileBERT fine-tune for two epochs. Each trained on up to ten messages; the same development cohort was evaluated at 5, 10 and 20 messages. TF-IDF receives text decoded from the same 128-token MobileBERT input budget; ModernBERT uses its own tokenizer and may retain a different span. Training initially became numerically unstable because MobileBERT's pooled values had extremely large magnitude. We applied layer normalization consistently to the pooled features during both training and ONNX export, then reran the experiment. This is a project-specific implementation choice, not a general conclusion about other MobileBERT checkpoints.

At ten messages, the sampled development set produced precision/recall of approximately 0.667/0.914 for TF-IDF and 0.821/0.914 for fine-tuned MobileBERT, with 35 positive and 174 negative segments. Each threshold was selected independently on the calibration sample to target at least 0.90 recall there. This is a promising pilot, not proof of a real-world improvement: the sample is small and not representative, labels are weak, PAN12 sources can reveal dataset-specific artifacts, and thresholds are not directly transferable to real prevalence.

We also ran a frozen-encoder ModernBERT-base probe on the exact same selected partitions. At ten messages it produced precision/recall of approximately 0.642/0.971. ModernBERT's encoder was not fine-tuned, whereas MobileBERT's was, so this is not an equal fine-tuning comparison. The three window sizes use the same cohort but the token budget is 128; 4 of 209 development examples were truncated at five turns, 5 at ten turns and 48 at twenty turns. An observed change with window size cannot therefore be assumed to represent successful use of all additional context. Reports and the pinned model revisions are recorded in [research.md](research.md).

We exported the fine-tuned MobileBERT to ONNX and compared CPU outputs against PyTorch on the development sample. The maximum probability difference was approximately 0.000002. We also tested dynamic signed INT8, unsigned INT8 and per-channel INT8. The per-channel file is approximately 27 MB versus 99 MB for the float model; its maximum probability difference was approximately 0.109, and after independently choosing a threshold on calibration it produced 31 true positives, 7 false positives and 4 false negatives versus 32, 7 and 3 for the float model. Quantization is therefore a candidate, not an interchangeable replacement. We separately fitted Platt scaling on the sampled calibration set and measured Brier score and ECE on development; the deliberately sampled prevalence means these calibration figures should not be assumed to hold in practice.

On the host Mac CPU, synthetic 128-token warm-inference measurements are available in [pan12-host-benchmark.json](pan12-host-benchmark.json). They do not measure an Android phone, energy use or battery. No phone was connected for device testing. At this point Verdict, Laya and the other decision-model proposals had been reviewed only at the documentation level; a later entry records the Verdict probe. No claims about sarcasm recognition or prompt-injection resistance were established. No new model was integrated into the Android application. Before integration, repeat the experiment on a larger, better audited split, assess the model on a genuinely independent source, validate export and tokenizer behavior on a phone, and determine an acceptable false-alert rate with relevant domain expertise.

We subsequently tested the released Verdict ONNX checkpoint locally as a zero-shot typed-decision probe on the shared PAN12 pilot. The fixed question asked about possible grooming and the available labels were true, false and insufficient evidence. The full prompt was capped at 128 tokens, so it does not receive exactly the same amount of conversational text as the other models. No additional training or PAN-specific probability calibration was performed; a decision threshold was selected on calibration as in the other pilot comparisons. At ten messages it produced 25 true positives, 171 false positives, 3 true negatives and 10 false negatives (precision 0.128; recall 0.714). This single question, weakly labeled sample and locally reproduced formatting are not a definitive assessment of Verdict, and the probe is not an equal comparison against a task-fine-tuned model. See [research.md](research.md) and [pan12-verdict-probe.json](pan12-verdict-probe.json). Laya was researched but not executed.

Finally, the TF-IDF input was restricted to text decoded from the same 128-token MobileBERT budget and the experiment was rerun. The reported figures above reflect that corrected comparison. The task fine-tune reproduced its previous 10-message development confusion counts. The public ModernBERT and Verdict checkpoint caches were removed after their probes to recover disk space; the research reports, scripts and locally exported MobileBERT artifacts remain available.

## 8 November 2026 — Phocinae and Laya follow-up

After additional disk space became available, we tested Phocinae-Largha on the same sampled PAN12 development and calibration partitions as the earlier models. We used the authors' dedicated runtime and a fixed English yes/no question without fine-tuning. To keep inputs constrained, the total decision input was limited to 128 tokens; batch inference using runtime internals was checked against the public API on a short synthetic input, not exhaustively. At the threshold selected on the calibration set, the ten-turn development result was 34 true positives, 172 false positives, 2 true negatives and 1 false negative (precision 0.165, recall 0.971). It is a prompt-dependent zero-shot pilot, not a definitive test of all Phocinae configurations. The same weak labels, artificial sample prevalence and source-bias limitations apply. Details and revisions are in [research.md](research.md) and [pan12-phocinae-probe.json](pan12-phocinae-probe.json).

We then executed Laya's English checkpoint and official runtime on the same sampled partitions and with the same yes/no question. Laya was tested zero-shot, with a 128-token total input budget and no PAN12 fine-tuning. Batched and single-input inference matched on one short synthetic case. At ten turns the sampled development comparison returned 31 true positives, 171 false positives, 3 true negatives and 4 false negatives (precision 0.153, recall 0.886); the threshold was selected on the separate sampled calibration set. The runtime emitted a temperature warning for `choice:11+`, a configuration not used by our `noul` question. We cannot conclude from this single prompt or this weakly labeled dataset that the model would perform the same after fine-tuning or on other data. The official PAN12 test set was not used.

Both probes record host batch-processing time, not phone latency or battery use. The results support keeping these zero-shot configurations out of the app for now; a fair architectural comparison would require matched task-specific training, comparable context and independently evaluated data. See [pan12-laya-probe.json](pan12-laya-probe.json), [pan12-phocinae-probe.json](pan12-phocinae-probe.json) and [research.md](research.md) for reproducibility and limitations.

### Follow-up — task-adapted Phocinae

We fine-tuned Phocinae's last two encoder layers and decision components, freezing the rest of the encoder and its unused action head. The two-epoch pilot used the same 360 training, 210 calibration and 209 development segments as the earlier MobileBERT comparison; 7.53 million parameters were trainable. The saved local parameter subset was reloaded against the pinned base checkpoint and reproduced the development confusion counts.

At the ten-message prefix, the comparison using a threshold selected on calibration yielded 34 true positives, 40 false positives, 134 true negatives and 1 false negative (precision 0.459; recall 0.971). This improves on the previous zero-shot probe's 172 false positives on that same sampled development set, but fine-tuned MobileBERT had 7 false positives and 3 false negatives. The sample is small, labels are derived from authors rather than individual messages, and separate thresholds were selected from the calibration sample. These findings do not establish model behavior on Instagram or actual grooming onset.

Both models use a nominal 128-token limit, but Phocinae's question and options leave only 93 tokens for conversation under its tokenizer; 25 of 209 ten-message development inputs were truncated. Its context and trainable layers therefore differ from MobileBERT's, so the comparison is not a controlled architecture study. No official test corpus, phone benchmark, model export or app integration was performed. The method, integrity check and aggregate report are recorded in [research.md](research.md) and [pan12-phocinae-finetune.json](pan12-phocinae-finetune.json).

### Follow-up — matched comparison prepared, run interrupted

We prepared a larger PAN12 experiment using 1,200 sampled training segments, 593 calibration segments and 563 development segments after the existing approximate near-duplicate audit. Its intended comparison gives MobileBERT and Phocinae the same raw conversational prefix that fits both tokenizers and partially fine-tunes the final two encoder layers of each. A deterministic development-only selection, independent checkpoint restoration check, and a separately guarded one-shot official-test procedure were also prepared. These new procedures have not yet been validated end-to-end and no model selection or official-test result has been produced.

The initial attempt loaded both models simultaneously and was interrupted after the first MobileBERT epoch when the system volume fell below 200 MiB free. It did not produce a usable selected model or a new evaluation. We revised the training procedure to load models sequentially, but did not restart it with the disk still critically full. Rebuildable Gradle and optional ModernBERT dependency caches were removed to recover space; they can be reinstalled as documented. No Android device was connected. Continue only once sufficient free disk space is available, validate the restored selection before opening the official test, and report any remaining source and near-duplicate leakage limitations.

## 9 November 2026 — matched comparison and held-out test

With approximately 3.1 GiB initially available, the sequential run completed while disk space was monitored. MobileBERT and Phocinae received the same raw text prefixes, up to ten messages, constrained to fit both tokenizers. Each had its final two encoder layers and decision components trained for two epochs on 1,200 sampled segments; 593 segments were used for threshold selection and 563 for development. Head architectures and numbers of trainable parameters differ, so this is a more controlled task comparison, not a perfectly matched architecture experiment. Fifty-eight development inputs were shortened to fit the shared budget. Labels remain weak author-derived labels and the dataset split has been used in exploratory work.

MobileBERT produced TP 60, FP 37, FN 10 (precision 0.619, recall 0.857); Phocinae produced TP 64, FP 22, FN 6 (precision 0.744, recall 0.914). The predetermined development selection chose Phocinae. Its locally saved weights were restored independently and reproduced the development confusion matrix. Thresholds are scores chosen for calibration-set recall and are not calibrated probabilities.

The selected weights and threshold were then frozen for a single evaluation on the official PAN12 test corpus. We excluded segments with authors seen anywhere in the training corpus and exact text overlaps, sampled 3,000 eligible segments uniformly, and removed 57 near duplicates against selected development data and training samples. The resulting 2,943 segments contained 62 author-labeled positives: TP 55, FP 138, TN 2,743, FN 7, precision 0.285 and recall 0.887. The false-positive burden is substantial. The near-duplicate check is incomplete, 174 short inputs were not checked by it, and exclusions remove a large portion of the original test corpus. The sampled test is not representative of Instagram, nor does the result validate detection of grooming in individual messages. The model has not been integrated into the app or tested on a phone.

Aggregate results and exact policies are in [pan12-matched-selection.json](pan12-matched-selection.json), [pan12-matched-validated.json](pan12-matched-validated.json), and [pan12-matched-test.json](pan12-matched-test.json). No conversations or author identifiers were written to these reports.

### Follow-up — qualitative synthetic conversations

We wrote ten short English conversations to probe the frozen Phocinae checkpoint and unchanged PAN12-selected threshold locally, using the same formatting and input budget as the held-out evaluation. None was truncated. These cases are deliberately illustrative, hand-written and far too few to estimate real-world performance; our qualitative intentions are not independently validated labels. Full invented conversations, raw scores and flags are recorded in [synthetic-chat-probe.json](synthetic-chat-probe.json), and the reproducible probe is `tools/synthetic_chat_probe.py` with the same environment as the matched comparison.

Two unambiguous invented scenarios involving an adult, a young teenager and requests for secrecy or a private photo fell below the flagging threshold. An innocuous conversation between two 14-year-olds, a sarcastic joke about dropping ice cream, and a benign surprise-party-style secret exceeded it. A bullying example also fell below the threshold; bullying is outside this model's PAN12 grooming-oriented task, so this does not evaluate a trained bullying classifier. The scores are uncalibrated and are not probabilities of grooming. Although the probe cannot measure deployment performance, these concrete errors reinforce the decision not to present this research checkpoint as a reliable grooming detector or integrate it into the app. No threshold was changed using these examples.

### Follow-up — controlled pairs and independent bullying corpus

We designed nine hand-written pairs varying a named feature and ran the frozen Phocinae and MobileBERT checkpoints on the same text, plus the app's toxic-BERT model on each final message separately. No case was truncated or used to adjust a threshold. Neither PAN12 model flagged the example involving an adult, a 14-year-old and a request for a private photo and secrecy. Phocinae's flag changed when only the opening was replaced with a gaming statement. It also flagged a literal remark but not the sarcastic counterpart in one pair; the toxicity model flagged a direct insult and threat but not their supportive variants. These probes demonstrate specific instabilities, not their cause or real-world performance. Full inputs and outputs are in [controlled-chat-probe.json](controlled-chat-probe.json).

We located and downloaded the authors' publicly shared CYBY23 Twitter workbook for a separate bullying-related diagnostic. Grouping by blank separator produced 111 threads and 636 nonempty messages, whereas the dataset page reports 112 and 639; the discrepancy remains unresolved. Comparing original thread labels against whether any message exceeded the unchanged toxic-BERT threshold gave TP 72, FP 32, TN 6, FN 1. This is a cross-task comparison: a thread's class 0 denotes aggression without bullying, and the model scores toxicity for individual messages. The high number of flagged threads and public-platform source prevent treating these numbers as a validated Instagram bullying detector. The aggregate report contains no source texts or IDs. Details, citations, other candidate datasets, access restrictions and the separation protocol are in [research.md](research.md). Restricted synthetic grooming benchmarks were identified but not obtained; no new grooming training or Android benchmark has been claimed.

### Follow-up — CYBY23 fine-tuning pilot and split audit

We fine-tuned MobileBERT's last two layers and a new head on CYBY23 thread labels and compared it with the existing per-message toxicity baseline. To reduce leakage, threads sharing a normalized exact message or an Excel tweet ID were grouped before splitting. The conservative ID grouping links a component of 19 threads (Excel IDs are floating-point values and may over-group). The resulting five-fold split was very unbalanced: 83 training, 24 development and only four test threads. The corpus had already been inspected as a whole, so even a larger test split would not constitute an untouched independent evaluation. Four cases cannot support a useful generalization estimate.

On development, the fine-tuned model flagged all 24 threads, including all ten negative-labeled examples; the toxicity baseline flagged 22. Both flagged all four test threads. This does not justify deployment or claim an improvement. The difference between a first-128-token thread classifier and the maximum of per-message scores also prevents an architecture-only conclusion. The report is [cyby23-bullying-pilot.json](cyby23-bullying-pilot.json); weights are local, research-only, and may contain memorized training information. We did not alter the app.

### Follow-up — expanded CYBY24 experiment

We downloaded the authors' CYBY24 workbook, a continuation of CYBY23, using the publicly listed CC BY-NC 4.0 Kaggle release. Its four labels include ordinary content, aggression without bullying, and two bullying severities. To reduce overlap with our earlier exploration, 31 threads sharing normalized exact text or a tweet ID with CYBY23 were excluded; six groups with missing or conflicting labels were also excluded. Exact-message and tweet-ID connected components were kept together across the subsequent split. This does not rule out paraphrases, author overlap, rounded-ID errors or overlap in model pretraining. The data are public Twitter threads, not private Instagram chats, and CYBY24 is not independent of CYBY23. The aggregate-only report records the source hash and protocol.

We trained the last two MobileBERT layers and a new binary head for two epochs on 1,652 threads, with 549 development and 551 held-out test threads. Its input was limited to the first 128 tokens, truncating 298 of the test threads. A different baseline applied the existing toxic-BERT model separately to all messages and flagged a thread if any message reached 0.5. Both thresholds were fixed at 0.5; selecting by development F1 picked the toxicity baseline. In the held-out split it had TP 66, FP 191, TN 248, FN 46 (precision 0.257, recall 0.589). MobileBERT had TP 89, FP 250, TN 189, FN 23 (precision 0.263, recall 0.795). The latter test result is reported transparently but cannot retroactively choose it as the development winner. Different input windows and aggregation, small modeling search, unknown overlap and source-specific labels prevent a clean architecture comparison or deployment claim.

Neither candidate is integrated into the app on the strength of these results. [cyby24-bullying-pilot.json](cyby24-bullying-pilot.json) and [research.md](research.md) document reproducibility, labels, licensing and limitations; no source text or user ID is in the reports. The local weight artifact is not approved for redistribution and has not been checked for memorization or run on Android.

### Follow-up — Gemma 4 E2B zero-shot

We downloaded the pinned 2.59 GB LiteRT-LM model to the external ORICO volume because the system volume lacked sufficient free space, verified SHA-256 against the published artifact, and ran it locally on the Mac CPU with LiteRT-LM 0.19.1. This is a host experiment, not an Android measurement. A fixed English prompt requested one of three labels and treated the chat as untrusted data. Thinking was disabled, sampling was greedy, and each conversation used a fresh session. Host load time was approximately 2.84 seconds, and the 28 short synthetic requests averaged approximately 0.30 seconds each; these host figures are not phone latency or battery measurements. The runtime also emitted audio-filter warnings despite text-only input; their impact has not been investigated.

On the ten previously written synthetic chats Gemma returned CONCERN for the two explicit adult/minor secrecy or photo examples missed by Phocinae, and NO_CONCERN for the two-teen friendship and the ice-cream joke Phocinae had flagged. It also returned NO_CONCERN on the bullying example. These cases are few and hand-written; the Gemma prompt covers bullying, threats and grooming while the previous Phocinae prompt targeted grooming alone. In the 18 additional controlled variants, one response was the out-of-schema word `bullying` and was recorded INVALID rather than forced into a class. These examples expose strengths and failures, not representative accuracy. Complete synthetic inputs and responses are in [gemma4-synthetic-probe.json](gemma4-synthetic-probe.json).

We also selected 30 positive and 30 negative threads with a fixed seed from the previously used CYBY24 test partition; the artificial 50% prevalence and prior inspection mean this is neither independent nor representative of Instagram. Gemma's fixed bullying-only prompt produced TP 23, FP 24, TN 4, FN 4 and five UNCERTAIN responses (three positives, two negatives). The fine-tuned MobileBERT on exactly the same cases had TP 24, FP 22, TN 8 and FN 6; toxic-BERT with maximum message aggregation had TP 14, FP 12, TN 18 and FN 16. All 60 Gemma outputs parsed correctly; abstentions were not silently treated as safe or harmful. The methods see different contexts, and the comparison does not isolate architecture or establish that any candidate is safe for deployment. No raw CYBY24 text or identifiers were saved in the [aggregate report](gemma4-cyby24-probe.json). The phone was not connected and the model was not integrated into the app.

### Follow-up — prompt selection and separate synthetic/real-text checks

To investigate prompt sensitivity, we fixed three candidate prompts before execution, including the original general-risk prompt. We selected using nine of the earlier synthetic cases; one ambiguous case was excluded. The selection rule, fixed beforehand, minimized `2 × false negatives + false positives + abstentions`, with ties broken alphabetically. These examples had already been seen during prior probing and are not an independent development set. Two prompts tied with zero observed errors; `context_first` won the prespecified tie break. The prompts and per-case outputs are in [gemma4-prompt-experiment.json](gemma4-prompt-experiment.json).

After selection we opened a distinct set of 22 new invented examples, balanced as 11 concerning and 11 innocuous according to our own intended labels. The baseline had TP 10, FP 1, TN 10, FN 1; `context_first` had TP 10, FP 1, TN 10, no ordinary FN and one invalid output on a concerning case. The invalid response was not converted into a label. Both falsely flagged the same teacher-and-student exchange; the baseline missed a repeated photo-mocking scenario, whereas the selected prompt returned `CERN` instead of a valid label for an adult/minor secrecy scenario. The test was authored by the same assistant who wrote the prompts and its labels were not independently reviewed. It is a small qualitative stress test, not a representative holdout or proof of improvement.

For a further exploratory check, the fixed baseline and selected prompt were run on 60 additional CYBY24 threads, balanced 30/30 by the original binary thread label and disjoint from the 60 previously run through Gemma. The original general-risk prompt returned 1 TP, 29 FN and 30 TN; the selected prompt returned 5 TP, 7 FN, 14 TN, 33 explicit UNCERTAIN and one invalid response (18 abstentions on positives, 16 on negatives). This is a severe sensitivity/coverage problem, not a successful reduction in false alarms. Original CYBY24 labels refer to bullying while these broader prompts also target grooming, serious threats and harmful conduct; the task mismatch limits confusion-matrix interpretation. The corpus was previously explored, label and author/near-duplicate uncertainty remains, and this balanced sample is not independent or representative. The [aggregate report](gemma4-prompt-cyby24.json) includes no original posts or identifiers. Neither prompt was integrated into the app.

### Follow-up — specialised model candidates

We identified [Vigil](https://huggingface.co/safecircleai/vigil), a Laya-based child-safety model with separate categories including grooming and bullying, as a relevant next research candidate. Its publisher reports using synthetic data only and notes 12–19% benign false alarms on two unseen text generators, about 49% false alarms in a friendly-teasing slice, single-label limitations and no phone test. The published Android LiteRT artifact is 1,289 MB; its latency measurements are on a server CPU, not Android. We have not downloaded or evaluated this model, and its SafeCircle Research License prohibits commercial use without permission. No vendor-reported results should be treated as our own test or as evidence of real-world reliability.

[compAnIonv1](https://huggingface.co/chatcompanion/compAnIonv1) is another lightweight grooming-specific candidate. Its model card lists PAN12 and PJZC in training, so our existing PAN12 evaluations would not be independent of its training and it cannot be assessed fairly on them as a held-out source. The next meaningful comparison needs a common input window, fixed category-specific thresholds, hard benign examples, an independently sourced test and a physical-device benchmark. The priority is evidence on individual harmful behaviors and false alarms, not assuming one model covers every safety task.

### Follow-up — Vigil and Horizon Mobile probes

We downloaded Vigil's f16 GGUF (658,804,800 bytes, pinned SHA-256 in the report) and Horizon Mobile INT4 (531,242,304 bytes) to external storage, and checked both hashes against their repository metadata. Their SafeCircle Research License permits non-commercial research and restricts commercial use. We built the specific Vigil llama.cpp fork revision recommended by its publisher for ARM64 CPU. The publisher's helper leaves a temporary file containing the input, so we modified the local CLI to accept JSON from standard input and avoided creating conversation files; the small reproducible change is in `tools/vigil-stdin.patch`. The modified wrapper matched the official helper's probabilities and flags exactly on one invented chat, not on a comprehensive parity suite.

We ran Vigil with the published fixed questions and thresholds on the same 32 previously used invented chats; one ambiguous example was not scored. Against the remaining author-intended labels, there were TP 15, FP 11, TN 5 and FN 0. These hand-written examples are not independent expert judgments or representative use. A separate check on the same balanced 60 CYBY24 threads used in the earlier Gemma pilot returned, for the bullying category alone, TP 21, FP 24, TN 6 and FN 9. Flagging any category instead returned TP 22, FP 24, TN 6 and FN 8. A bullying thread label is not equivalent to every possible risk category; counts must be read accordingly. No original CYBY24 message or author ID was exported. Full synthetic examples are in [vigil-synthetic-probe.json](vigil-synthetic-probe.json); aggregate real-text results are in [vigil-cyby24-probe.json](vigil-cyby24-probe.json).

Horizon Mobile INT4 loaded using LiteRT-LM 0.19.1 on CPU, but none of the 31 scored synthetic examples yielded a usable boolean `risk_detected` plus consistent category in our setup. First, the model card's no-extra-system-instruction route mostly echoed input; then, with the Horizon Full card's explicit system message, the model returned JSON with fields or types inconsistent with the published schema (for example a string where the risk boolean was requested). One separately tried explicit chat-template example also lacked the advertised boolean. We did not infer labels by guessing from malformed outputs, and no accuracy was calculated. The experiment does not establish that Horizon fails on other runtimes, its INT8 variant, or Android. The two synthetic logs are [horizon-no-system-probe.json](horizon-no-system-probe.json) and [horizon-synthetic-probe.json](horizon-synthetic-probe.json). No Android phone was connected, no network/storage behavior was measured on a phone and neither model was integrated into our app.

### Follow-up — choosing further research baselines

We identified a further bullying-oriented candidate, [RoBERTa fine-tuned for cyberbullying](https://huggingface.co/nayan90k/roberta-finetuned-cyberbullying-detection), whose card states Apache 2.0 and training on a balanced mixture of public social-media sources. Its published in-source results and claimed robustness are not an independent validation for Instagram; source overlap and conversation-level behavior still need checking. For grooming, [compAnIonv1](https://huggingface.co/chatcompanion/compAnIonv1) is specialised but its training sources include PAN12, so our earlier PAN12 test cannot be presented as independent evaluation. The [early predator detection project](https://early-sexual-predator-detection.gitlab.io/) also offers trained BERT/MobileBERT baselines and an Android demo, while explicitly cautioning that its models are not ready for real-world use.

The resulting research direction is to compare separate bullying and grooming candidates with task-matched labels and the same text windows, leave thresholds and any cascade decisions to calibration data, and assess false positives and false negatives on genuinely independent sources. The existing CYBY24 and synthetic probes were used for exploratory model and prompt selection and cannot be relabelled as an untouched final test. No new model was downloaded, tested or integrated in this review, and none has yet been selected as a validated real-world detector.
### Follow-up — RoBERTa, matched context and an external abuse corpus

We tested the published Apache-2.0 `nayan90k/roberta-finetuned-cyberbullying-detection` checkpoint, revision `a5c86fdb6aa46b7d41261907e6c6ecbb2cf66907`, without retraining. Its weights have SHA-256 `9cf3d24e3d64cbad3778219fb24a3e0390a523b50b878f41a99ca0b3656e57df`. On the previously inspected balanced 60-thread CYBY24 sample, first-128-token classification produced TP 17, FP 21, TN 9, FN 13; the maximum over individual messages produced TP 27, FP 29, TN 1, FN 3. These strategies change the input as well as aggregation and neither is satisfactory. See [the aggregate probe](roberta-cyby24-probe.json); a separate [synthetic probe](roberta-synthetic-probe.json) excludes grooming and threats from its bullying score.

We then compared four classifiers using the same raw CYBY24 thread prefixes, limited to fit a 256-token budget for each tokenizer including the Phocinae question. MobileBERT, ModernBERT and Phocinae were trained with two epochs, last two layers and head, using the same split and optimizer protocol; the published RoBERTa was used as supplied. Heads, trainable parameter counts, training histories and tokenization differ. A development threshold maximized precision subject to at least 0.80 recall on development; these scores are not calibrated probabilities. On the 551 previously explored test threads (112 positives), MobileBERT had TP 100, FP 365, TN 74, FN 12; ModernBERT TP 88, FP 236, TN 203, FN 24; Phocinae TP 96, FP 260, TN 179, FN 16; and RoBERTa TP 75, FP 255, TN 184, FN 37. The common prefix truncated 174 threads. Results are exploratory, the source is public Twitter rather than Instagram, and possible author, paraphrase and pretraining overlap remain. A nominal test split previously examined for model development is not an independent holdout.

Reloading each checkpoint reproduced its development confusion matrix using the original batch size and padding. An initial single-item validation did not reproduce every count; the cause was not established. The additional 60-case comparisons use single-item inference, so threshold sensitivity and implementation differences must be investigated before treating their results as interchangeable with the batch-four results. Seven models, including Toxic-BERT, Vigil and Gemma, were run on that common prefix; [the detailed research notes](research.md) record why their different training objectives and thresholds limit comparisons.

After space became available, we ran Gemma 4 E2B with its previously fixed bullying prompt on the same 60 balanced CYBY24 threads and common prefixes: TP 21, FP 26, TN 3, FN 5, plus five explicit UNCERTAIN responses (four positives and one negative). On the 100-example ConvAbuse sample it produced TP 46, FP 8, TN 33, FN 3, plus ten UNCERTAIN responses (one positive and nine negatives). No invalid responses or inference errors were reported. We retain uncertainty separately rather than forcing a binary prediction. The prompt asks for bullying while ConvAbuse labels an abusive utterance, and neither experiment is a grooming test. Gemma's token limit was not independently audited; both runs were on the Mac CPU, not a phone. Aggregate results: [CYBY24](cyby24-matched60-gemma.json), [ConvAbuse](convabuse-external-gemma.json).

For a source outside CYBY, we used the public [ConvAbuse corpus](https://github.com/amandacurry/convabuse) ([paper](https://aclanthology.org/2021.emnlp-main.587/), CC BY 4.0). We selected 100 official-test examples, balanced 50/50, one per conversation, with at least two unanimous annotators; 188 ambiguous, disputed or insufficiently annotated records were excluded. Exact overlap with CYBY messages was checked, but paraphrases and pretraining overlap were not. These are user-to-chatbot interactions, not peer Instagram chats; the annotation concerns an abusive user utterance, not necessarily thread-level bullying or grooming. With the previous thresholds unchanged, MobileBERT had TP 41, FP 32, TN 18, FN 9; ModernBERT TP 16, FP 2, TN 48, FN 34; Phocinae TP 50, FP 36, TN 14, FN 0; RoBERTa TP 48, FP 3, TN 47, FN 2; Toxic-BERT TP 47, FP 0, TN 50, FN 3; Vigil TP 48, FP 34, TN 16, FN 2. This small consensus-only sample is selected and artificially balanced, so the results are a transfer diagnostic, not an estimate of real-world accuracy or evidence of grooming detection. No Android performance was measured.

The Instagram-related Insta-CTSR dataset is a possible future external source, but its file is access-restricted; its metadata license does not grant file access. No application or message was sent to its owners. A larger independently annotated, conversation-level peer-chat evaluation and a physical-phone benchmark remain necessary before selecting or deploying a model.
