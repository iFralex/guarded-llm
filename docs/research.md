# AWARE and research datasets

## AWARE review

Reviewed [awareframework/aware-client](https://github.com/awareframework/aware-client) at commit `f77e873baaedfc649fd39ca8f3547f914c3e6b32`, Apache-2.0. It is the AWARE client, not evidence that it is the separate AWARE-Light framework named in the proposal. Its `aware-core/.../Applications.java` traverses accessibility nodes, suppresses duplicates and skips password nodes; its screen-text sensor buffers screen contents, inserts records into a content provider and broadcasts events. It also includes many unrelated sensors, permissions and study/synchronization machinery. It cannot establish that Instagram exposes message nodes or distinguish chat messages just by using AccessibilityService.

Decision: retain the small Android app, rather than replace it or import the framework. We independently added checks for a non-interactive screen, password events, password input types and visible nodes, while preserving a strict package allowlist, no editable-field collection and in-memory processing. An in-memory bounded queue now avoids dropping all but the first candidate from an accessibility update. No AWARE source code was copied. These checks do not prove that content extraction works or that no sensitive content can ever be exposed. A physical-device test remains necessary.

## Candidate datasets

- **Dadvar, Trieschnigg and de Jong, YouTube**: [University of Twente record](https://research.utwente.nl/en/datasets/underlying-dataset-of-experts-and-machines-against-bullies-a-hybr/), [Zenodo metadata](https://zenodo.org/api/records/10143096). The archive is published CC BY 4.0 and includes an original citation. The downloaded file has SHA-256 `a0271497653cc8907052e57d8ff9bc0cc22faab461bc3c92355b1fc14cca9450`. Its 3,464 usable rows consist of author histories (417 positive and 3,047 negative), not labeled individual messages or private chats. The [creator's dissertation](https://ris.utwente.nl/ws/files/6031140/thesis_M_Dadvar.pdf) describes the collection and annotation; comments date from 2012. Profile fields and histories must not be confused with a modern Instagram conversation dataset. The original archive stays locally in `data/external/`, excluded from version control.
- **PAN 2012 sexual predator identification**: [shared task](https://pan.webis.de/clef12/pan12-web/sexual-predator-identification.html) and [dataset DOI](https://doi.org/10.5281/zenodo.3713280). A relevant English conversation benchmark for future grooming research, with train/test materials and author/line-level tasks. Its positives include adults interacting with volunteers posing as minors; it is old, sensitive, source-biased and does not establish performance on Instagram. Verify the archive's actual terms and institutional research/handling requirements before download, reuse or redistribution. It is not bundled and is not used by the current toxicity model.
- **Wisconsin Bullying Traces**: [original research page](https://research.cs.wisc.edu/bullying/data.html) describes 7,321 annotated tweets, including roles and teasing. Access requires a [use agreement](https://research.cs.wisc.edu/bullying/agreement.txt) with notification and no-transfer conditions. Not downloaded; the project owner must decide whether to accept those conditions.
- **Ejaz et al., comprehensive cyberbullying dataset**: [Mendeley v2, CC BY 4.0](https://data.mendeley.com/datasets/wmx9jj2htd/2), [dataset paper](https://arxiv.org/abs/2402.10231). Some text was collected from existing sources, but the authors explicitly generated the users and assembled exchanges synthetically. It is not a corpus of real conversations. One cited upstream Mendeley source has been [removed at its author's request](https://data.mendeley.com/datasets/jf4pzyvnpj/1); review provenance and upstream rights before reuse. A third-party CB2 card describes school participants; the primary paper says the user profiles and interactions were generated synthetically, so do not rely on that claim. This is potentially useful for controlled experiments, not natural dialogue validation.

## Reproducing the exploratory experiment

```sh
.venv/bin/python tools/fetch_dadvar.py
HF_HOME="$PWD/.cache/huggingface" .venv/bin/python tools/evaluate_dadvar.py
```

The model is unchanged and was not trained or calibrated on this dataset during this work. The experiment samples 100 authors per class using seed 42 and classifies only the first 128 tokens of each author's comments using the pre-existing 0.5 toxicity threshold. The sample is deliberately balanced; it does not preserve prevalence. The resulting comparison is between a toxicity score and an author-history bullying label, so it is a cross-task exploratory diagnostic, not message-level test accuracy, grooming evaluation, or an estimate of deployment performance. Truncation, unknown overlap with original model training data, original sampling, label semantics, source and age all limit interpretation. Results are in `docs/dadvar-exploratory.json`; no text or personal identifiers are exported in the report. Do not use these data to label individuals in the app.

For subsequent research, define the actual task and labels first, group splits by author and conversation, deduplicate across datasets, check model-training overlap, preserve a completely held-out test set and report class prevalence. For grooming, use a separate context-aware task and avoid treating toxicity scores as ground truth.

## PAN12 contextual development experiment

Run `.venv/bin/python tools/pan12_context_experiment.py` with the previously downloaded archive. The script verifies its SHA-256 and reads only the **official training** ZIP; the official test data is not used. It builds a research-only offline baseline from up to the first 10 messages per segment, using word unigram/bigram TF-IDF and class-weighted logistic regression. No model or conversation text is exported. The current Android app is unchanged.

PAN12's positive ground truth identifies authors, not independently labeled grooming messages. For this experiment a segment is provisionally positive if it includes a labeled author, and positive prefixes are included only if they contain a turn by that author. This is a **weak author-derived label**, not evidence that the first ten messages themselves show grooming. All authors appearing in each full segment, and identical case-folded prefix texts, are connected before splitting. This grouping uses the full segment solely for separation, not as input to the predictor. It reduces exact author/text overlap but cannot guarantee independence or remove paraphrases and dataset-specific cues.

A fixed-seed group split selected without looking at model predictions produced 57,858 training segments (1,834 positive) and 9,043 development segments (179 positive). The largest connected component alone contains 22,506 segments; it prevents a simple 20% holdout and makes development composition sensitive to the grouping. At an untuned 0.5 threshold, the development results were 159 true positives, 20 false negatives, 366 false positives and 8,498 true negatives: precision **0.303**, recall **0.888**, F1 **0.452**, and average precision **0.736**. These are exploratory within-source metrics, not performance on Instagram, at deployment prevalence, on the official test set, or for detecting grooming in individual messages. The high number of false positives matters operationally; class-weighted scores are not calibrated probabilities. The fixed 10-turn prefix and test construction do not establish real-time or early-warning effectiveness.

Full methodology and machine-readable results are in [pan12-context-development.json](pan12-context-development.json). Future experiments must check near-duplicate and source leakage, select thresholds on development only, hold out entire authors and conversation sources where possible, and reserve the official test for a separately designed final assessment. Avoid mixing PANC and PAN12 without checking their shared source material.

## PAN12 model and optimization pilot

See [pan12-model-comparison.json](pan12-model-comparison.json), [pan12-quantization.json](pan12-quantization.json), [pan12-host-benchmark.json](pan12-host-benchmark.json), and the development diary for the current pilot. Only the original training corpus is read; no official test records are opened by the scripts. Outputs and model weights are local, under ignored `reports/` and `artifacts/`, and must not be treated as production models.

The shared sampler groups all authors appearing anywhere in a segment and exact duplicate text in 5-, 10- and 20-turn prefixes before splitting. It samples 360 training examples, 210 calibration examples and 209 development examples from separate components. For the selected samples, it also removes near-duplicates across partitions using 10-turn word-trigram Jaccard >= 0.8; windows under eight trigrams are not checked. This is an incomplete near-duplicate audit, not a guarantee of independence. The split is a small resource-bounded pilot with deliberately altered prevalence. Positive labels are inherited from author labels, and positives must have a labeled author's turn within the first five messages; labels do not establish grooming onset.

Models use identical selected partitions. TF-IDF is given text decoded from the first 128 MobileBERT tokens, while ModernBERT has its own tokenizer and may retain a different span. A TF-IDF classifier and MobileBERT variants train on ten-message inputs; evaluations also use 5 and 20 messages from the same cohort. MobileBERT uses layer-normalized pooled output: the unnormalized output had extreme magnitude and caused unstable training. We compare a frozen encoder with a trained logistic head against a two-epoch end-to-end fine-tune. The fixed 128-token limit may truncate much of the input, especially for longer windows; count and report this before drawing conclusions about added context. A recall-targeting threshold is selected on the calibration sample, while a separate development sample is used for metrics. The sampled class distributions mean measured precision, thresholds and calibration do not necessarily transfer to real use. The test set must not be used for iteration.

Run the experiments after following README setup:

```sh
HF_HOME="$PWD/.cache/huggingface" HF_HUB_OFFLINE=1 TOKENIZERS_PARALLELISM=false .venv/bin/python tools/pan12_model_comparison.py
HF_HOME="$PWD/.cache/huggingface" HF_HUB_OFFLINE=1 TOKENIZERS_PARALLELISM=false .venv/bin/python tools/evaluate_quantization.py
HF_HOME="$PWD/.cache/huggingface" HF_HUB_OFFLINE=1 .venv/bin/python tools/benchmark_pan12_onnx.py
```

The pilot requires the pinned MobileBERT revision in the local Hugging Face cache. The comparison script writes unquantized and quantized ONNX weights and reports probabilities and errors; the quantization script separately selects thresholds and fits Platt scaling on the calibration split, reporting Brier score and 10-bin ECE on development. These are calibration checks on an artificially sampled population, not evidence of deployment calibration. The host benchmark uses synthetic input and does not measure Android latency, battery consumption or device memory. Raw text and author IDs are not included in reports.

ModernBERT can be tested as a separate frozen-encoder probe under a newer isolated Transformers installation: `pip install --no-deps --target .modern-deps -r tools/requirements-modernbert.txt`, followed by `PYTHONPATH="$PWD/.modern-deps" HF_HOME="$PWD/.cache/huggingface" HF_HUB_OFFLINE=1 MODERNBERT_REVISION=8949b909ec900327062f0ebf497f51aef5e6f0c8 USE_TF=0 .venv/bin/python tools/pan12_modernbert_probe.py`. The pinned checkpoint must first be downloaded; do not send PAN12 text to an external inference service. The frozen probe is not a full fine-tune and must be compared accordingly.

The supplied claims about speed, probability calibration and prompt-injection immunity are hypotheses, not verified results. [Laya's own model card](https://huggingface.co/convaiinnovations/laya) reports overconfidence and a need for task-specific calibration; its English decision model uses a more limited effective input budget than the backbone's maximum context. [Verdict's model card](https://huggingface.co/heman10x/rlcd-modernbert-151m) documents a different, typed-decision interface. Neither typed scores nor encoder architecture establish immunity to adversarial content or sarcasm. These candidates require separate, matched-task and on-device experiments; the preliminary Verdict probe below is not a complete comparison. No automatic cascade or fixed 0.10/0.85 thresholds have been validated.

### Verdict zero-shot probe

The [Verdict checkpoint](https://huggingface.co/heman10x/rlcd-modernbert-151m), revision `8af2496eb63c7fa66d7d234e1f62629380030eb4`, was tested locally with `tools/pan12_verdict_probe.py` using the same sampled calibration and development partitions. It used a single fixed grooming proposition and three choices (true, false, insufficient evidence), with no task fine-tuning. The score for the true choice was thresholded using the calibration set; it must not be treated as a PAN12-calibrated risk probability. The complete prompt, including label descriptions, has a 128-token budget, so the available chat text can differ from that retained for the other models. Tokenization uses the checkpoint's tokenizer JSON directly and verifies its two special token IDs. Outputs and the official formatting were inspected, but independent equivalence with the author's full SDK has not been established; this is a preliminary implementation test, not a definitive evaluation of Verdict.

For the ten-turn development prefix, the zero-shot probe produced 25 true positives, 171 false positives, 3 true negatives and 10 false negatives (precision 0.128; recall 0.714). Results are prompt-dependent, and comparing this zero-shot decision task with a supervised fine-tuned classifier is not a controlled architecture comparison. The model is not suitable for inclusion in the app on this evidence. No PAN12 text was sent to a remote inference API; aggregate results are in [pan12-verdict-probe.json](pan12-verdict-probe.json). Laya and Phocinae were subsequently executed on the sampled PAN12 data; see the follow-up entries below.

To reproduce the Verdict probe, first install the separate ModernBERT dependencies as above and download only the published checkpoint files into the local Hugging Face cache with `snapshot_download('heman10x/rlcd-modernbert-151m', revision='8af2496eb63c7fa66d7d234e1f62629380030eb4', allow_patterns=['model.onnx','tokenizer.json','tokenizer_config.json','config.json','calibrator.json'])`. Then run `PYTHONPATH="$PWD/.modern-deps" HF_HOME="$PWD/.cache/huggingface" HF_HUB_OFFLINE=1 USE_TF=0 .venv/bin/python tools/pan12_verdict_probe.py`. The temporary Verdict and ModernBERT checkpoint caches were removed after the tests to recover disk space; no data or training examples need to be uploaded to retrieve those public weights.

### Phocinae-Largha zero-shot probe (8 November 2026)

The pinned [Phocinae-Largha checkpoint](https://huggingface.co/Phocinae/Phocinae-Largha-150M-v1) (`a57030322df13c8c55ab7a99b8b7b176e2c5aa85`) was evaluated offline on the same sampled PAN12 calibration and development partitions with its official [phocinae-server](https://github.com/Phocinae/phocinae-server) runtime (`f751d7258e50b4cd19fe3967ae184ed895ce68b5`). This is a zero-shot `noul` decision with one fixed question, not a supervised model trained on PAN12. The total input, including the question and options, was deliberately capped at 128 tokens, with a 64-token head budget. Different tokenizers and prompt overhead mean the models do not necessarily see the same exact text. A custom batched use of runtime internals was checked against its public API on one short synthetic example; the altered token budget and private API mean full runtime equivalence remains unproven.

At ten turns, the probe returned 34 true positives, 172 false positives, 2 true negatives and 1 false negative (precision 0.165, recall 0.971) after selecting a threshold for at least 0.9 recall on the separate sampled calibration split. The experiment does not establish a useful model for deployment or characterize all prompts and variants. Results and the pinned revision are in [pan12-phocinae-probe.json](pan12-phocinae-probe.json); `tools/pan12_phocinae_probe.py` performs the test locally. No PAN12 test corpus or remote inference service was used.

### Laya zero-shot probe (8 November 2026)

The [Laya English checkpoint](https://huggingface.co/convaiinnovations/laya), revision `7b928d828b7b0e022f929d9bd2e44165aa270148`, was evaluated offline on the same sampled calibration and development partitions as Phocinae, using the authors' [Laya runtime](https://github.com/NandhaKishorM/laya), revision `3c346a2f8b542838eed6a1d210aa378c79e71c4c`. We asked the same English `noul` question without PAN12 fine-tuning. The input budget was 128 tokens total, including the question and options, with a 64-token head budget. Each runtime has its own tokenizer and formatting, so neither the effective context nor the resulting scores are guaranteed equivalent. The Laya public batched and single-input APIs matched on one short synthetic example; this is not a comprehensive parity test.

At ten turns, the development result was 31 true positives, 171 false positives, 3 true negatives and 4 false negatives (precision 0.153, recall 0.886), using a threshold selected on the separate sampled calibration partition. The checkpoint runtime warned that a temperature for `choice:11+` was out of range and replaced it; the experiment uses the `noul` question type, not that choice configuration. The warning is recorded rather than treated as evidence that these scores are calibrated. Aggregate results, pinned revisions and the batch processing times on the host are in [pan12-laya-probe.json](pan12-laya-probe.json). These timings include batching and preparation on the Mac CPU and are not per-message phone latency or battery measurements.

The two zero-shot probes target a different question and training regime from the fine-tuned MobileBERT experiment. PAN12's author-derived labels, small sampled evaluation, source artifacts and different prompt budgets remain material limits. The results do not justify deploying either zero-shot model or excluding the possibility that another prompt, fine-tuning method or dataset could perform differently. The official PAN12 test corpus was not evaluated.

To reproduce the probes, install `tools/requirements.txt` and the separate `tools/requirements-modernbert.txt` as described above. Clone the two official runtime repositories locally and check out their exact commits cited in these entries. Download each pinned model revision with `huggingface_hub.snapshot_download`, preserving its `model.safetensors`, `rl_agent_config.json`, `encoder/` and `tokenizer/` files. With `HF_HOME` pointing to that cache and `HF_HUB_OFFLINE=1`, run `PHOC_RUNTIME=<phocinae-server-checkout> .venv/bin/python tools/pan12_phocinae_probe.py` and `LAYA_RUNTIME=<laya-checkout> PYTHONPATH="$PWD/.modern-deps" USE_TF=0 .venv/bin/python tools/pan12_laya_probe.py`. Both scripts read only the original PAN12 training archive and write aggregate metrics; never publish raw messages or user identifiers.

### Fine-tuned Phocinae pilot (8 November 2026)

We fine-tuned the last two encoder layers, final normalization, type embeddings, decision head and scorer of the pinned Phocinae checkpoint for two epochs; all earlier encoder layers and the action head remained frozen. This trained 7,534,849 of 144,292,867 parameters on the same 360 sampled PAN12 training segments used in the MobileBERT pilot. The 210 calibration and 209 development segments are the same author-grouped, approximately deduplicated samples as before. We used a fixed `noul` question, weighted cross-entropy and AdamW; no official PAN12 test data were accessed.

On the ten-message development prefix, the fine-tuned model returned 34 true positives, 40 false positives, 134 true negatives and 1 false negative (precision 0.459, recall 0.971, average precision 0.784). For comparison, its prior zero-shot probe returned 34, 172, 2 and 1; fine-tuned MobileBERT returned 32, 7, 167 and 3 respectively. Each model's decision threshold was independently selected on the calibration sample to target recall of at least 0.90 there. These results are not proof of generalization: the sampled development set has 35 positives, author-derived weak labels and altered prevalence, and the threshold selection is uncertain.

Both neural models have a 128-token sequence limit, but the comparison is not strictly input-matched: Phocinae spends tokens on the typed question and options, leaving **93 tokens for conversation**, with its own tokenizer. Of 209 development segments, Phocinae truncated 5 at the five-message prefix, 25 at ten messages and 61 at twenty messages. MobileBERT's reported ten-message truncation count was 5 using its different tokenizer. Models also differ in which layers were trained and in optimization parameters. Therefore this is a task-adapted pilot comparison, not evidence that an architecture is intrinsically superior.

Training and evaluation are reproducible with `PHOC_RUNTIME=<pinned-phocinae-server-checkout> HF_HOME="$PWD/.cache/huggingface" HF_HUB_OFFLINE=1 .venv/bin/python tools/pan12_phocinae_finetune.py`. It saves the trained subset of parameters in ignored `artifacts/pan12-phocinae-finetune/trainable.safetensors`, plus an aggregate report. The pinned original checkpoint is required to reconstruct the model. `tools/validate_phocinae_finetune.py` restores those weights, verifies their SHA-256 and reproduced the ten-message development confusion counts. The weight artifact is research-only and was not assessed for memorization, Android execution or redistribution; it has not been integrated into the app. The experiment and limits are recorded in [pan12-phocinae-finetune.json](pan12-phocinae-finetune.json).

### Matched-prefix comparison and official test

On 9 November we trained MobileBERT and Phocinae with the same sampled partitions and raw prefixes, capped at ten messages and a budget that fits both tokenizers. Each model's last two encoder layers and decision components were trained for two epochs. The models' heads, tokenizers, and trainable parameter counts differ. Of 563 development inputs, 58 were truncated. On the development set, MobileBERT had TP 60, FP 37, TN 456 and FN 10 (precision 0.619, recall 0.857); Phocinae had TP 64, FP 22, TN 471 and FN 6 (precision 0.744, recall 0.914). A prespecified selection rule chose Phocinae and independent restoration reproduced its development confusion matrix. See [selection](pan12-matched-selection.json) and [restoration verification](pan12-matched-validated.json). Scores and thresholds are not calibrated probabilities.

The frozen model and threshold were evaluated once on a uniformly sampled subset of the official PAN12 test corpus after excluding authors seen in training and exact text matches. From 155,128 original segments, 48,822 were excluded for author overlap and 2,870 for exact text overlap; after additional eligibility filtering, 3,000 of 103,387 eligible segments were sampled. A partial near-duplicate audit removed 57, leaving 2,943 segments, including 62 author-labeled positives. The result was TP 55, FP 138, TN 2,743 and FN 7: precision 0.285, recall 0.887 and F1 0.431. See the [test report](pan12-matched-test.json). These estimates describe the filtered sample, not the whole corpus or Instagram. The author-based labels do not establish grooming in each text, 174 short samples escaped the near-duplicate check, other source artifacts and pretraining overlap remain possible, and the development partitions had been used for earlier exploration. In particular, this result does not justify deploying the model as a grooming detector.

To reproduce, prepare the pinned MobileBERT and Phocinae checkpoints and the official PAN12 archive as described above, check out phocinae-server at `f751d7258e50b4cd19fe3967ae184ed895ce68b5`, set `PHOC_RUNTIME` to its path, `HF_HOME` to the local model cache and `HF_HUB_OFFLINE=1`, then run `tools/pan12_matched_train.py` and `tools/validate_matched_selection.py` with `.venv/bin/python`. The separately guarded `tools/pan12_matched_test.py` refuses to overwrite its existing report and requires the verified frozen selection. Keep the corpus and trained weights private pending their applicable terms and memorization assessment. None of these measurements is an Android latency, memory or battery benchmark.

### Controlled synthetic perturbations

Nine pairs of invented three-turn chats change one named element such as age, secrecy, request for a photo, a gift, sarcasm, insult or threat. Frozen Phocinae and MobileBERT receive the same full conversation prefix and their own fixed PAN12-selected thresholds; the existing toxic-BERT ONNX model separately receives only the last message at its existing 0.5 threshold. These models solve different tasks and the results are not directly comparable accuracy estimates. None of the inputs was truncated. All texts, exact settings, scores and flags are in [controlled-chat-probe.json](controlled-chat-probe.json); reproduce with `PHOC_RUNTIME="$PWD/.cache/phocinae-server" HF_HOME="$PWD/.cache/huggingface" HF_HUB_OFFLINE=1 TOKENIZERS_PARALLELISM=false .venv/bin/python tools/controlled_chat_probe.py`. The runtime and models must be present at the pinned revisions.

Both PAN12 models failed to flag the example with an adult, a 14-year-old and a request for a private photo and secrecy. When only the first turn was changed to a gaming interest, Phocinae's score rose above its threshold, while MobileBERT remained below. Phocinae also flagged the literal but not the sarcastic version of one ice-cream dialogue, and flagged both the insulting and supportive endings in another pair. Toxic-BERT flagged the isolated insult and threat but not their supportive variants. These hand-written examples expose instability, but do not identify a causal mechanism, establish sarcasm competence, or estimate generalization. Their scores are not calibrated probabilities and no threshold was changed.

### CYBY23: exploratory bullying-related comparison

The [CYBY23 corpus](https://opendata.usm.my/items/f351c23f-009f-4b8f-bba3-563f5fb1bbfd), by Alfurayj, Yee and Lutfi, contains public Twitter threads and thread-level aggression/bullying categories. Its authors request citation of their two TENCON 2023 papers, given in [the aggregate report](cyby23-exploratory.json). The public record describes 112 threads and 639 tweets; the downloaded workbook parses as 111 blank-delimited nonempty groups and 636 nonempty text cells under our procedure. This discrepancy is unresolved and is not silently corrected. The workbook is kept locally in ignored `data/external/cyby23.xlsx` with the report's SHA-256; source terms beyond the stated public-use and citation request should be checked before redistribution.

For this cross-task exploration, a thread is labeled positive for original class 1 or 2, and the pre-existing toxic-BERT classifier flags a thread if any individual message scores at least 0.5. On the 111 parsed threads (73 positives), this gives TP 72, FP 32, TN 6 and FN 1. Class 0 represents aggression without bullying rather than ordinary harmless dialogue. A toxicity model applied to messages is being compared with a thread-level bullying label, and flagging any message makes results sensitive to thread length and bystander text. The corpus is small, source and pretraining overlaps are unknown, and it is not representative of private Instagram messages. This is not evidence of bullying detection accuracy on Instagram. Reproduce locally with `TOKENIZERS_PARALLELISM=false HF_HOME="$PWD/.cache/huggingface" .venv/bin/python tools/evaluate_cyby23.py`; no tweet text or identifiers are written to the aggregate report.

### Independent-data and future evaluation protocol

The [PCCD paper](https://doi.org/10.3390/data11030051) reports 1,668 annotated Chinese–English Twitter sessions, and its [CC BY 4.0 archive](https://zenodo.org/records/18860813) provides tweet IDs, annotations and restoration instructions. The public package requires restoration from tweet data; we have not established API access or recovered its texts. Its code-mixed, profanity-filtered public threads are not a direct English Instagram benchmark. [SynBullying](https://huggingface.co/datasets/arrkaa-NLP/SynBullying) includes role-play and synthetic dialogues with sarcasm labels, but its files are gated and terms are restricted. [LURE](https://research.unipg.it/handle/11391/1631297) is synthetic and its full grooming corpus is restricted; [TUT-100](https://huggingface.co/datasets/tuteliq/tut-100) is also gated, synthetic and evaluation-only. These are candidates, not datasets obtained or validated by us. User consent cannot substitute for the dataset owner's access approval.

Before a new training comparison, define message- and context-level annotation guidelines with explicit uncertain cases and obtain independent expert review; record annotator agreement. Reserve a separate independent source as a final test before inspecting its contents or metrics, split development by conversation and connected authors, remove exact and approximate overlaps, and retain ambiguous or sarcasm cases as separate evaluation slices. Record source, date, license, task, label provenance and class prevalence. The present synthetic pairs and CYBY23 have already been inspected and are development diagnostics, not an untouched test. Do not use model-generated annotations as unquestioned ground truth, and do not train on held-out cases. A meaningful comparison requires the same partitions and contexts, a frozen threshold per model, and a report of false negatives, false positives and confidence intervals. Access to a suitable independent grooming corpus and phone-side validation remain open.

### CYBY23 and CYBY24 task-adaptation pilots

The [CYBY23 training pilot](cyby23-bullying-pilot.json) fine-tuned MobileBERT but classified every one of the 24 development threads as positive, including 10 negatives. A conservative grouping by repeated Excel tweet IDs and exact normalized text yielded only four held-out threads. One ID-linked component had 19 threads; Excel's floating-point ID representation may cause over-grouping. This corpus had been examined before the split and cannot yield an untouched final test. These results are not a basis for integration.

The authors describe [CYBY24](https://syaheerah.com/datasets-for-sharing/) as a continuation of CYBY23 with 2,789 threads and more than 13,000 tweets. The [Kaggle release](https://www.kaggle.com/datasets/sllresearchgroup/cyber-bystander-role-labelled-dataset-cyby24) metadata states CC BY-NC 4.0. Its downloaded ZIP has SHA-256 `fad01343cc62e58558101ff15d27bb484efe38ac1cfe31930aab55dd490a3be2` and remains in ignored `data/external/cyby24.zip`. Its labels distinguish normal content, aggression without bullying, and low- or high-aggression bullying; the last two are grouped as positive for this binary pilot. It is public Twitter data, not private Instagram chats, and overlaps the CYBY23 research lineage.

We excluded 31 CYBY24 threads with an exact normalized message or tweet ID matching CYBY23 and six blank/conflicting-label groups; within CYBY24, connected groups sharing an exact normalized message or tweet ID were kept in the same split. Excel IDs are floats and can collide or lose precision. Paraphrases, shared authors and pretraining overlap are not fully audited. The resulting development/test experiment used 1,652 training, 549 development and 551 test threads. MobileBERT's final two layers and binary head were trained for two epochs; input was truncated to the first 128 tokens, including 298 of 551 test threads. The separate toxic-BERT baseline scores every message and flags the thread if any score exceeds 0.5, so its effective input and aggregation differ. Both fixed thresholds were 0.5. The development F1 rule selected toxic-BERT; the locked test result was TP 66, FP 191, TN 248 and FN 46 (precision 0.257, recall 0.589). MobileBERT's held-out result was TP 89, FP 250, TN 189 and FN 23 (precision 0.263, recall 0.795), reported for transparency and not used retroactively for selection. See [aggregate metrics](cyby24-bullying-pilot.json).

These numbers are an exploratory within-source test after limited prior exposure to a related corpus. They do not validate either approach on Instagram, do not resolve fairness or calibration, and should not drive deployment. A controlled architecture comparison would use comparable context and an independently sourced, audited holdout. Reproduce with the project dependencies, the archived dataset at the path above, local pinned MobileBERT weights and ONNX toxicity assets, then run `HF_HOME="$PWD/.cache/huggingface" HF_HUB_OFFLINE=1 TOKENIZERS_PARALLELISM=false .venv/bin/python tools/cyby24_bullying_pilot.py`. It refuses to overwrite its existing report. Research weights remain local and may memorize training text; no source posts are written to aggregate reports. Android performance was not measured.

### Gemma 4 E2B local zero-shot probes

The CPU experiment used [Gemma 4 E2B LiteRT-LM](https://huggingface.co/litert-community/gemma-4-E2B-it-litert-lm), revision `6b78abd019e61a1ca4cbe3b212d2c9ce8ff38a94` and SHA-256 `181938105e0eefd105961417e8da75903eacda102c4fce9ce90f50b97139a63c`, with LiteRT-LM 0.19.1. The 2.59 GB artifact was stored on an external volume. This was local host inference, not an Android measurement. Per [Google's documentation](https://ai.google.dev/gemma/docs/core), mobile memory estimates cover weights and exclude additional runtime/context costs; actual phone support and performance require a physical-device test. On the host, loading took 2.84 seconds and the 28 short synthetic cases averaged 0.30 seconds per response; no phone latency, memory or energy was measured. The runtime emitted audio filter warnings for text input, with unknown impact.

On the ten original invented chats, Gemma correctly marked two obviously concerning adult/minor scenarios that the earlier Phocinae experiment had not flagged; it did not flag the benign friendship and joke that Phocinae flagged. It also did not flag the explicitly hostile bullying example. The prompts differ: Gemma was asked about grooming, bullying or threats, while Phocinae was asked about grooming only. On 18 further controlled variants one output failed the exact requested format and is recorded INVALID. Inputs, fixed prompt, raw responses and timing are in [synthetic report](gemma4-synthetic-probe.json). This is qualitative testing on hand-written examples, not a benchmark, and outputs are not calibrated probabilities.

On a fixed random balanced sample of 60 threads from the already evaluated CYBY24 test partition, Gemma's separate bullying-only prompt returned TP 23, FP 24, TN 4, FN 4 and five explicit UNCERTAIN outputs (three positive labels and two negative labels). Every output parsed as a requested label. On the same 60 cases MobileBERT returned TP 24, FP 22, TN 8, FN 6; toxic-BERT with maximum message aggregation returned TP 14, FP 12, TN 18, FN 16. All thresholds and prompts were fixed before this comparison. The sample was deliberately balanced, drawn from a previously examined source, and is not an independent holdout or an Instagram prevalence estimate. The three systems use different prompts, truncation and aggregation, so this is not a controlled architectural study. See [aggregate CYBY24 report](gemma4-cyby24-probe.json). No source text or identifiers are written to it.

Install the additional pinned dependency from `tools/requirements-gemma.txt` into the project environment, obtain the exact `.litertlm` artifact and verify its SHA-256. ### Prompt sensitivity and separate examples

We defined three general-risk prompts and selected by minimum `2 × FN + FP + abstentions` on nine previously seen synthetic examples, with ties resolved alphabetically. The selected `context_first` prompt and one other tied without observed error on development. The held-out synthetic cases were not read by the script before selection, but were authored by the same assistant who designed the prompts, without independent human annotation; they are illustrative rather than a blinded, representative benchmark. They are recorded in [gemma4-prompt-holdout.json](../data/gemma4-prompt-holdout.json). On 22 cases balanced 11/11, the earlier prompt produced TP 10, FP 1, TN 10, FN 1; the selected prompt produced TP 10, FP 1, TN 10, zero ordinary FN and one invalid output on a positive. The same benign adult teacher/minor exchange was flagged by both. Selection and all case outputs are in [gemma4-prompt-experiment.json](gemma4-prompt-experiment.json). This is not evidence that the selected prompt generalizes better.

A further fixed comparison used 60 CYBY24 threads (30 positive, 30 negative) disjoint from the earlier Gemma sample, using seed 71 from the same previously used test partition. The earlier general-risk prompt returned TP 1, FN 29, TN 30 and FP 0. The selected prompt returned TP 5, FN 7, TN 14, FP 0, and 34 abstentions (18 on positives, 16 on negatives), of which 33 were explicit UNCERTAIN and one was out of format. Abstentions must not be treated as correct negatives or positives. See [gemma4-prompt-cyby24.json](gemma4-prompt-cyby24.json). CYBY24's labels describe bullying, whereas the prompts request a broader risk decision including threats or grooming; the source is not independent, class balance is artificial, and annotation and leakage limitations remain. The large variation compared with the prior bullying-specific prompt supports testing task definitions and prompt sensitivity; it cannot establish why responses changed because the sampled threads also differ. Neither prompt is ready for deployment.

Reproduce using the pinned Gemma artifact and environment described above: run `.venv/bin/python tools/gemma4_prompt_experiment.py --model <model-path>` and `.venv/bin/python tools/gemma4_prompt_cyby24.py --model <model-path> --backend cpu`. The latter requires the existing CYBY23/CYBY24 archives; its report stores counts only, not original text or IDs. These runs were on the Mac CPU, not Android.
